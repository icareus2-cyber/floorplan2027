# Floor Plan 2027: guide for AI assistants

A home-design app that runs entirely in the browser: draw a floor plan in 2D, view it in 3D, export it.
Plain HTML + CSS + JavaScript, **no build step, no framework, no npm dependencies**. The only external
library is three.js r128 (plus OrbitControls), loaded from a CDN the first time the 3D view opens.

## Run it

```
python -m http.server 8027      # from the project folder, then open http://localhost:8027
```
`.claude/launch.json` holds the same command. Opening `index.html` directly also mostly works.
There is no test suite: check changes by running the app (a headless browser such as Playwright works well).

## Data model

- **Units:** everything is stored in **centimetres**. Metres / feet-inches exist only in the UI (`Settings → Units`).
- **Plan coordinates:** x to the right, y down the plan; the top of the plan is north; the front (entrance) of Wizard/Demo houses is the bottom edge.
- **State** (`app.js` → `state`): `items[]`, `levels[]` (`{id:'L0', name, elev, wallH}`; `L0` = ground floor), `level` (the one being edited), `zoom/panX/panY`, `grid`, `snap`, `align`, `tool`…
- **An item** (`newItem()`): `{id, type, x, y, w, h, r, fx, fy, stroke, fill, fillNone, sw, opacity, label, showLabel, locked, t (wall thickness), lvl, wh (wall height)}` plus type-specific fields. `x, y` is the top-left before rotation `r` (degrees).
- **Style** (`state.style`: `western` / `japanese`, saved with the plan; the default for new plans and the Wizard in Settings → Style, `floorplan2027.style`; the open plan's in Plan settings → Style; `FP.style()`, `FP.setStyle()`): two layers. The *look* switches at once — in `view3d.js` (`isJP()`) furniture is lower and simpler in light wood (`spec()`: beds, sofas, chairs, tables, `JP_BLOCKS`) and tiled roofs get `japaneseRoofDetails()` (stacked-tile ridge with end tiles, hip caps, dark bargeboards) and timber soffits. The *defaults* apply to what is added from then on (`app.js`): Japanese sizes (`JP_SIZES`, beds 97 / 140 × 195), roofs `roofJP()` (70 cm eaves, 25°) in `kawara` tiles (`roofMatOf`). Japanese pieces (any style): doors `door-shoji`, `door-fusuma`, `door-amado` (board), `door-koshi` (lattice; all sliding, shut by default); windows `window-shoji`, `window-koshi` (lattice outside the glass); icons in the "Japanese style" category (`futon`, `zataku`, `kotatsu`, `genkan`, `engawa` — a veranda on posts with a lean-to eave, back edge on the wall — `oshiire`, `tokonoma`, `stone-lantern`, `tsukubai`, `fence-bamboo`); wall materials in the 'japanese' group (`itabari` cedar boards, `yakisugi`, `shikkui`); roof coverings `kawara` and `kayabuki` (thatch); the `tatami` floor material, the `irimoya` roof (`FP_ROOFS.irimoya`: the hipped part `it.irimoyaHip`, default 0.35 of half the depth). Export for AI describes the style (`scene.style`).
- **Support under a raised ground floor** (`state.support`: `basement` / `plinth` / `mound` / `none`, saved with the plan): when the ground floor is above the outside ground with no basement, opening 3D asks how it is held up (section `support under a raised ground floor` in `app.js`). `basement` adds a level with concrete copies of the outer walls and slabs, `mound` adds a plateau `hill` item, `plinth` is drawn by `plinthBand()` in `view3d.js` only. `FP.houseSupport()` tells the 3D view which.
- **Floor slabs:** auto-fit slabs (`it.autoFit`, `slabFit()`) follow the walls. A slab on the ground (`onGround()`: no storey below its level) is the house's base plate: 'loop' / `true` fit the outer faces of the walls (the walls stand on it, shortened by its thickness); slabs carried by the walls below fit within the outer walls, unless `it.outerFit` (demo op `slab` with `outer: true`; the Wizard's slab over its basement, whose walls stop under it) — then they also run out to the outer faces.
- **Stairs:** start = what they stand on + `it.z` (`stairBottom()`); stairs lifted onto a slab top (`it.z > 0`) keep their start when a floor is laid under them (`fillFloorAt()`); top = `it.topZ`, else `it.rise`, else the level above. `it.z < 0` sinks them (at most `BURY_MAX` = 5 m): the steps below the floor or ground are buried, and slab snapping leaves that start alone.
- **Hip roof shape:** `it.hipRidge` (0 … 0.95, unset = equal slopes) is the ridge's share of the roof's length; `FP_ROOFS.hip(W, D, it)` in `icons.js` gives the end depth, the ends' pitch factor and overhang factor (eaves level all round). The plan symbol, `buildRoof()` and `roofTopAt()` in `view3d.js` all use it.
- **Roof view (plan):** with the working height at or above a roof's eaves on the current level (`roofViewOn()`), `render()` draws the roofs (then chimneys and roof windows) on top and fades everything else (`ROOF_VIEW`, `.off-height`), so roof lines can be seen and edited.
- **Move axis** (`state.moveAxis`, the XY / Z / A pad in the plan and 3D view): 'z' (the default), 'xy', 'a' (all: dragging any object moves every item on every level together — `shiftAll()` also moves auto-fit slab seeds; `FP.moveAll(dx, dy)` for the 3D view) or 'none'. The choice stays until another is picked.
- **Warnings and Auto-fix:** a warning in Properties is an element with `data-fix="<code>"` (and `data-fix-v` for a value the panel worked out). `decorateFixes()` adds an Auto-fix button to each and a bar on top; `applyFix()` in `app.js` holds one case per code. A new warning should get a code and a case.
- **Change → commit:** after changing `state.items`, call `render()` and `commit()` (pushes undo history and saves). `buildProps()` refreshes the properties panel.
- **Browser storage keys:** `floorplan2027.plan` (the plan), `.wizard` (Wizard answers), `.theme`, `.units`, `.iconCat`, `.prefabCat`, `.prefabShell`, `.stairHeight`, `.sunOverhead`, `.photoai` (Photo → House provider/model; the API key only if the user ticks "remember"). A second tab is detected and stops saving (the "changed in another tab" guard).

## `window.FP` (the editor's API for other scripts)

`byId, items(), selectedId(), selectedIds(), levels(), currentLevel(), demoBuild(house, onEdit), toast(text, kind)`, plus helpers used by the 3D view (`storeyRise, stairRise, floorRel, prefabPreviewItems`…). See the `API for the 3D view` section at the end of `app.js`.

## How to…

- **Add an icon:** add an entry to `js/icons.js` in the right category; it appears in the palette automatically.
- **Add a sample house:** add to `FP_DEMOS` in `js/demo.js` using the documented ops; add a 3D thumbnail in `img/demo/`.
- **Add a Wizard question:** add a key to `DEFAULTS`, a step in `STEPS`, and use it in `design()`; `setAnswers()` validates against `options()`, so add the new key there too.
- **Add a dialog / feature module:** create `js/<name>.js` as an IIFE that reads `window.FP`, mount its markup on first use (see `wizard.js` `mount()`), add the script to the list in `index.html` and its button to the top bar, style it with the theme variables.
- **Add a toolbar action:** buttons carry `data-act="…"`; handlers are in the `toolbar & file actions` section of `app.js`.

## Conventions

- Vanilla ES2020, each file an IIFE with `'use strict'`; communicate through the `window.FP*` globals only.
- Comments explain *why* in plain sentences; keep the existing comment style and the British spelling used in the UI ("colour", "storey", "metres").
- No new dependencies. Everything must keep working offline except the 3D view (CDN), Photo → House (the AI provider, or the local model's first download) and Map → House (OpenStreetMap).
- Never send the user's data anywhere except where they asked (Photo → House sends only the chosen photos to the provider they picked; Map → House sends only the typed address and its location to OpenStreetMap's services).
